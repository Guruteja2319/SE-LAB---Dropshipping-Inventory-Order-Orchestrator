# Static Code Analysis — Tournament Scoreboard

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| Shell command execution | Security (High) | 69–71 | `os.system()` executes a shell command constructed using the `server` input. Untrusted input could lead to command injection. Bandit reports B605. | Replace `os.system()` with `subprocess.run()` using a list of arguments and `shell=False`. Validate the server value and handle execution errors. |
| Insecure temporary-file creation | Security (Medium) | 64–66 | `tempfile.mktemp()` generates a temporary filename without securely creating the file, creating a potential race condition. Bandit reports B306. | Replace `tempfile.mktemp()` with a secure temporary-file API such as `tempfile.NamedTemporaryFile()`, with appropriate cleanup. |
| Hardcoded referee password | Security (Low) | 6 | The password `referee-demo` is stored directly in the source code. Anyone with access to the code can read it. Bandit reports B105 with medium confidence. | Avoid storing real credentials in source code. Use a protected environment variable or secrets manager if authentication is required. |
| Standard pseudorandom generator | Security review | 60–61 | `random.choice()` is used for the coin toss. Bandit reports B311 because the standard `random` module is unsuitable for cryptographic purposes. | Use `secrets.choice()` if the toss requires security-sensitive unpredictability. For a simple demonstration, the existing implementation may be acceptable. |
| Mutable default argument | Bug / Code quality | 11 | `addTeam(teamName, players=[])` uses a mutable list as a default argument. Changes to the list could be shared across calls. Pylint reports W0102. | Use `players=None` and create a new list inside the function when no player list is supplied. |
| Naming convention violations | Code quality | 11, 16, 25, 42, 47, 51, 56, 60, 64, 69 | Function and parameter names such as `addTeam`, `homeGoals`, and `teamName` use camelCase instead of Python's recommended `snake_case`. Pylint reports C0103. | Rename functions and parameters to `add_team`, `home_goals`, and `team_name`, and update all references consistently. |
| Missing docstrings | Code quality | 1, 11, 16, 25, 42, 47, 51, 56, 60, 64, 69, 74 | The module and several functions do not explain their purpose through docstrings. Pylint reports C0114 and C0116. | Add a module docstring and concise docstrings to the functions. |
| Unnecessary `elif` after `return` | Code quality | 17–20 | `matchResult()` uses `elif` after the preceding `if` branch returns. Pylint reports R1705. | Replace the `elif` with a separate `if` statement while preserving the result logic. |
| Repeated comparisons in top-two check | Code quality | 56–58 | `isTopTwo()` compares the team separately with `table[0]` and `table[1]`. Pylint reports R1714. The function also needs consideration for a league with fewer than two teams. | Use membership testing, such as `team_name in table[:2]`, to simplify the comparison and handle short tables safely. |
| Whitespace before dictionary colon | Formatting | 5 | `POINTS = {"win" : 3, ...}` contains unnecessary whitespace before the colon. Flake8 reports E203. | Remove the extra space: `{"win": 3, ...}`. |
| Missing blank line between functions | Formatting | 60 | There is only one blank line before `tossCoin()`. Flake8 reports E302. | Add two blank lines between top-level function definitions. |
| Missing whitespace after comma | Formatting | 79 | The match call contains `2,1` instead of `2, 1`. Flake8 reports E231. | Add a space after the comma. |
| Insufficient spacing before inline comment | Formatting | 87 | The inline comment does not have the required spacing before `#`. Flake8 reports E261. | Add at least two spaces before the inline comment. |
| Missing match-input validation | Potential logic issue (manual review) | 25–39 | `recordMatch()` assumes both team names exist and that goal values are valid. Invalid names or negative/non-numeric goals could cause errors or incorrect standings. This is a manual-review finding, not a reported finding from the three tools. | Validate that both teams exist, are different, and have valid non-negative integer scores before updating statistics. |
| Empty league handling | Potential logic issue (manual review) | 56–58 | `isTopTwo()` indexes the first two entries of the league table without checking its length. It can raise an `IndexError` when fewer than two teams are registered. This is a manual-review finding. | Check the number of teams before accessing positions, or use `team_name in table[:2]`. |
